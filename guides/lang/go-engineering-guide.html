实战练习

题目：写一个函数 FormatAlert(title, level string, timestamp ...string) string，返回格式化告警字符串。level 默认为 "warning"；timestamp 为可选参数，不传则用当前时间。

参考答案 
package main

import (
    "fmt"
    "strings"
    "time"
)

func FormatAlert(title, level string, timestamp ...string) string {
    if level == "" {
        level = "warning"
    }
    ts := time.Now().Format("2006-01-02 15:04:05")
    if len(timestamp) > 0 && timestamp[0] != "" {
        ts = timestamp[0]
    }
    return fmt.Sprintf("[%s] %s - %s", strings.ToUpper(level), ts, title)
}

func main() {
    fmt.Println(FormatAlert("CPU 使用率超过 90%", ""))
    fmt.Println(FormatAlert("磁盘已满", "critical", "2026-09-12 09:00:00"))
}

函数与方法

Go 函数的核心特征：多返回值（尤其是 error）、命名返回值、defer 延迟执行。错误不是异常，而是正常的返回值。

多返回值与命名返回值

// 多返回值（Go 最常用模式之一）
func Divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, fmt.Errorf("division by zero")
    }
    return a / b, nil
}

// 命名返回值（defer 中可修改）

    alert, err = db.Get(id)

值接收者 vs 指针接收者

// 值接收者：不修改原 struct
func (a Alert) Summary() string {
    return a.Title
}

// 指针接收者：可修改 + 避免大 struct 拷贝
func (a *Alert) SetLevel(level string) {
    a.Level = level
}
规则：需要修改 struct 或 struct 较大时用指针接收者；小 struct 只读用值接收者。同一类型的方法接收者应保持一致。
// 一等函数
type Handler func(ctx context.Context, msg string) error

func Process(h Handler, msg string) error {
    return h(context.Background(), msg)
}

// 闭包
func Counter() func() int {
    n := 0
    return func() int {
        n++
        return n
    }
}

defer 关键字

func ReadFile(path string) ([]byte, error) {
    f, err := os.Open(path)
    if err != nil {
        return nil, err
    }
    defer f.Close()  // 函数返回前执行，LIFO 顺序

    return io.ReadAll(f)
}

// defer 执行顺序：后进先出（LIFO）
defer fmt.Println("1")
defer fmt.Println("2")
defer fmt.Println("3")
// 输出: 3, 2, 1

实战练习

题目：实现 Retry(fn func() error, maxAttempts int) error，失败时重试直到成功或达到最大次数。

参考答案 
func Retry(fn func() error, maxAttempts int) error {
    var lastErr error
    for i := 0; i < maxAttempts; i++ {
        if err := fn(); err == nil {
            return nil
        } else {
            lastErr = err
        }
    }
    return fmt.Errorf("after %d attempts: %w", maxAttempts, lastErr)
}

错误处理

💡
Go 哲学：错误是值，不是异常。每个可能失败的操作都返回 error，调用方必须显式处理。这让错误路径清晰可见，但代码中会有大量 if err != nil。

基本模式

result, err := doSomething()
if err != nil {
    return fmt.Errorf("doSomething failed: %w", err)
}
// 继续使用 result

Panic / Recover

// panic：程序不可恢复的错误（类似 Python 未捕获异常）
// 只在真正无法继续时使用，如 init 失败、编程 bug

// recover：在 defer 中捕获 panic
func SafeHandler(w http.ResponseWriter, r *http.Request) {
    defer func() {
        if rec := recover(); rec != nil {
            log.Printf("panic recovered: %v", rec)
            http.Error(w, "Internal Server Error", 500)
        }
    }()
    // 业务逻辑...
}
何时用 panic：几乎不用。业务错误返回 error；只在 init、不可恢复的内部 bug 时用 panic。不要用 panic 做流程控制。

并发模式

// Fan-out：一个 producer，多个 worker 消费
func worker(id int, jobs <-chan string, results chan<- string) {
    for job := range jobs {
        results <- fmt.Sprintf("worker-%d: %s", id, job)
    }
}

// Fan-in：多个 channel 合并为一个
func merge(chs ...<-chan string) <-chan string {
    out := make(chan string)
    var wg sync.WaitGroup
    for _, ch := range chs {
        wg.Add(1)
        go func(c <-chan string) {
            defer wg.Done()
            for v := range c { out <- v }
        }(ch)
    }
    go func() { wg.Wait(); close(out) }()
    return out
}

// Worker Pool
const numWorkers = 5
jobs := make(chan string, 100)
for w := 0; w < numWorkers; w++ {
    go worker(w, jobs, results)
}

实战练习

题目：实现一个 Worker Pool：5 个 worker 并发处理 alert ID，主 goroutine 发送 20 个任务并收集结果。

参考答案 
func WorkerPool(ids []string, workers int) []string {
    jobs := make(chan string, len(ids))
    results := make(chan string, len(ids))
    var wg sync.WaitGroup
    for w := 0; w < workers; w++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for id := range jobs {
                results <- "processed:" + id
            }
        }()
    }
    for _, id := range ids { jobs <- id }
    close(jobs)
    wg.Wait()
    close(results)
    var out []string
    for r := range results { out = append(out, r) }
    return out
}

接口与多态

Go 接口是隐式实现：只要类型实现了接口的所有方法，就自动满足该接口。无需 implements 关键字。这是 Go 多态的核心。

接口定义与实现

// 定义接口
type AgentRunner interface {
    Run(ctx context.Context, prompt string) (string, error)
    Stream(ctx context.Context, prompt string) <-chan string
}

// CursorRunner 自动满足 AgentRunner（无需声明）
type CursorRunner struct { APIKey string }

func (c *CursorRunner) Run(ctx context.Context, prompt string) (string, error) {
    // 调用 Cursor API...
    return "analysis result", nil
}

func (c *CursorRunner) Stream(ctx context.Context, prompt string) <-chan string {
    ch := make(chan string)
    go func() { defer close(ch); ch <- "chunk" }()
    return ch
}

// 多态调用
func Analyze(runner AgentRunner, prompt string) (string, error) {
    return runner.Run(context.Background(), prompt)
}

    return func(c *gin.Context) {
        token := c.GetHeader("Authorization")
        if token == "" {
            c.AbortWithStatusJSON(401, gin.H{"error": "unauthorized"})
            return
        }
        c.Next()
    }

// 熔断器（简化版）
type CircuitBreaker struct {
    failures  int
    threshold int
    open      bool
    mu        sync.Mutex
}

func (cb *CircuitBreaker) Call(fn func() error) error {
    cb.mu.Lock()
    if cb.open {
        cb.mu.Unlock()
        return errors.New("circuit open")
    }
    cb.mu.Unlock()
    err := fn()
    cb.mu.Lock()
    if err != nil {
        cb.failures++
        if cb.failures >= cb.threshold { cb.open = true }
    } else { cb.failures = 0 }
    cb.mu.Unlock()
    return err
}

func FetchWithTimeout(url string, timeout time.Duration) ([]byte, error) {
    ctx, cancel := context.WithTimeout(context.Background(), timeout)
    defer cancel()
    req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
    if err != nil { return nil, err }
    resp, err := http.DefaultClient.Do(req)
    if err != nil { return nil, err }
    defer resp.Body.Close()
    return io.ReadAll(resp.Body)
}

面试高频题

goroutine 和 thread 的区别？

goroutine 是 Go runtime 管理的轻量级协程，初始栈约 2KB，可动态扩缩；由 Go 调度器做 M:N 映射（M 个 goroutine 映射到 N 个 OS thread）。

OS thread 由内核调度，栈通常 1-8MB，创建/切换成本高。

Go 调度器使用 GMP 模型：G（goroutine）、M（machine/OS thread）、P（processor/逻辑 CPU）。goroutine 阻塞时（如 channel、syscall），调度器会将 M 上的其他 G 迁移到其他 M，避免 thread 浪费。

channel 是如何实现的？

channel 底层是 hchan 结构体，包含：

  • 环形缓冲区（ring buffer）：有缓冲 channel 用 fixed-size 数组存储数据
  • mutex：保护 channel 内部状态
  • sendq / recvq：等待发送/接收的 goroutine 队列（sudog 链表）

无缓冲 channel：发送方和接收方必须同时就绪（同步握手）。有缓冲 channel：缓冲区未满时可异步发送。关闭 channel 后，接收方读到零值 + false。

Go 的 GC 是如何工作的？

Go 使用三色标记清除（tricolor mark-and-sweep）并发 GC：

  • 白色：未被访问的对象（待回收）
  • 灰色：已被访问但子对象未扫描
  • 黑色：已被访问且子对象已扫描

GC 大部分时间与 mutator（用户代码）并发执行。仅在标记终止（mark termination）阶段有短暂 STW（Stop-The-World），用于完成最终标记。Go 1.5+ 目标 STW < 1ms。

defer 的执行顺序？

LIFO（后进先出）。多个 defer 按注册的反序执行。

defer fmt.Println("1")
defer fmt.Println("2")
defer fmt.Println("3")
// 输出: 3, 2, 1

defer 的参数在注册时就确定了值（非执行时），但闭包变量在执行时读取最新值。defer 有一定性能开销，热路径避免滥用。

slice 的底层结构？

slice 是三个字段的描述符（24 字节 on 64-bit）：

type slice struct {
    array unsafe.Pointer  // 指向底层数组
    len   int               // 当前元素数
    cap   int               // 底层数组容量
}

切片操作 s[low:high] 共享底层数组——修改 sub slice 可能影响原 slice。append 超出 cap 时分配新数组（通常 2 倍扩容）并拷贝。

map 是并发安全的吗？

不是。并发读写 map 会导致 fatal error: concurrent map read and map write。

解决方案：

  • sync.Mutex / sync.RWMutex 保护 map
  • sync.Map：适合读多写少或 key 相对固定的场景
  • 使用 channel 传递数据，避免共享 map
context 的用途？

context.Context 提供三种能力：

  • 取消（Cancellation）：WithCancel — 父 context 取消时，所有子 context 自动取消
  • 超时/截止（Timeout/Deadline）：WithTimeout / WithDeadline
  • 值传递（Value）：WithValue — 传递 trace ID 等请求级元数据（谨慎使用）

在 HTTP handler → service → DAO 调用链中传递 context，确保客户端断开或超时时，所有下游操作都能及时终止。

interface 是如何实现的？

Go interface 底层是 iface（含方法的接口）或 eface（空接口）：

type iface struct {
    tab  *itab           // 类型信息 + 方法表
    data unsafe.Pointer // 指向实际数据
}

itab 包含：接口类型、具体类型、方法指针数组。类型断言就是查 itab 是否匹配。空接口 eface 只有 type 指针 + data 指针，无方法表。

这也是为什么 nil interface 不等于 nil：interface 值为 nil 需要 type 和 data 都为 nil。
